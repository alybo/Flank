# Работа над Flank

Перед изменениями прочитать `docs/PROJECT.md`, аудит и последующие `CHANGES-*.md` в `docs/`. Аудит от 09.09.2026 — исторический baseline; часть дефектов исправлена 10.09.2026. Проверить `git status --short --branch`: название текущей ветки не определяет актуальную концепцию продукта.

## Назначение

Утилита macOS прячет выбранное **окно** за край экрана и возвращает его, как Slide Over на iPad. Рабочий UI выбирает конкретное AX-окно из списка или жестом Control + Shift + drag. Поддерживается одно окно и выбираемый внешний левый/правый край; жест экспериментален до реальных испытаний. Не возвращать автоматический выбор первого окна приложения по bundle ID.

## Инварианты для доработок

- Не терять окно: восстановить прежнюю цель перед заменой; сохранять возможность повторить восстановление при AX-ошибке.
- Пауза скрытия сохраняет AX-привязку; отвязка очищает её только после успешного возврата. Смена стороны сначала восстанавливает окно. Жест отвязки проверяет UUID и сохраняет позицию до drag.
- Повторный hide/show должен быть безопасен. Не сохранять скрытый или промежуточный кадр анимации как позицию возврата.
- Отмена анимаций, таймеров и отложенного раскрытия должна распространяться на смену цели, отключение режима и восстановление.
- Не смешивать AX/CG-координаты с AppKit. Преобразовывать их явно; выбирать экран по видимому кадру и учитывать изменение дисплеев.
- Проверять ошибки и типы данных Accessibility. UI-состояние должно отражать результат операции.
- Управлять конкретным окном. PID нестабилен между запусками; bundle ID идентифицирует приложение, но не окно.
- Не добавлять сетевые сервисы, телеметрию, приватные API или привилегированные helpers без задачи, которая этого требует.

Эти инварианты — целевые требования; аудит перечисляет места, где существующий код им не соответствует.

- Для изменений менеджера запускать `bash scripts/run-audit-tests.sh`; текущий baseline: 119/119 PASS. Исторический baseline аудита: 3 успешных и 9 неуспешных проверок. Не менять ожидание ради зелёного вывода.
- Проверять Debug/Release сборки по масштабу изменения. `xcodebuild test` пока не настроен; успешная сборка не означает отсутствие функциональных ошибок.
- AX в тестовом harness подменён. Он не доказывает работоспособность реальных приложений, Spaces, полноэкранных окон или нескольких мониторов.
- Для реальных AX-проверок использовать отдельные тестовые окна без несохранённой работы. В отчёте различать выполненные проверки и оставшуюся ручную матрицу.
- При изменении поведения обновлять `docs/PROJECT.md`; результаты исправлений добавлять отдельным датированным разделом/документом, сохраняя исходные выводы аудита.
