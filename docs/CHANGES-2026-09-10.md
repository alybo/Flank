# Исправления восстановления окна — 10.09.2026

Первый этап после аудита `AUDIT-2026-09-09.md`. Исторический аудит и его протокол сохранены без изменения. Исправления находятся в рабочем дереве текущей ветки; merge, commit, push и удаление веток не выполнялись.

## Изменённое поведение

- Повторный hide не перезаписывает положение возврата. Разворот анимации сохраняет последний устойчивый видимый frame.
- Привязка нового окна начинается только после успешного возврата прежнего. При отказе прежняя цель остаётся доступной для повторного возврата.
- Один отменяемый animation timer заменяет 14 независимых отложенных команд. Восстановление, отключение и смена цели останавливают старую анимацию; callbacks проверяют timer identity и UUID сессии.
- AX-клиент проверяет CF-типы, тип AXValue, успешность чтения, конечность координат и положительный размер. Ошибка read/write/raise переводит менеджер в `unavailable`, сохраняя цель и безопасную позицию.
- После завершения перемещения выполняется readback. Успешный код AX без фактического изменения позиции не считается успешным перемещением; допуск — 1 point.
- Неудачный возврат не очищает состояние. Команда «Вернуть окно и выключить» в меню/настройках останавливает автоматические действия и позволяет повторить возврат. Ошибка отображается в настройках и отмечается в меню.
- При обычном Quit сначала возвращаются окна. При отказе пользователь может остаться для повторной попытки или явно выйти без возврата. Принудительное завершение по-прежнему не защищено.
- Таймеры скрытия отменяются при смене настроек и переходах состояния. Перед выполнением проверяют актуальные настройки, сессию, курсор, видимость и активное приложение. Уход курсора после перехода в другое приложение заново оценивает неактивность.
- Reveal delay отменяется при уходе с края, обновлении настроек, восстановлении и смене состояния. Callback проверяет наведение и актуальную сессию. Позднее раскрытие после активации владельца дополнительно проверяет, что он всё ещё активен.
- Завершение приложения-владельца освобождает состояние, в том числе после неудачного возврата: окна этого процесса больше нет.
- Ширина кромки применяется к текущему скрытому окну сразу. Настройки нормализуются при загрузке, применении и сохранении; предотвращено переполнение legacy PID.

## Сопутствующие изменения

- Геометрия AX преобразуется в AppKit явно относительно основного дисплея. Индикатор и cursor hit test больше не используют эвристику «проверить обе системы координат». Overlay выбирает экран по сохранённому видимому кадру.
- Mouse monitors читают кеш, а не геометрию AX при каждом движении. Добавлен local monitor для событий самой утилиты. Кеш обновляется каждые 0.4 с только в состоянии visible; неизменённый frame не публикуется повторно. Это снижение числа вызовов по структуре кода, не измеренный выигрыш CPU/fps.
- Убрано дублирующее initial apply; повторные одинаковые значения настроек фильтруются. Launch/terminate нерелевантных приложений не пересоздают overlay и не сбрасывают таймеры.
- Реестр восстанавливает окна вне NSLock и возвращает общий результат. Галочка меню синхронизируется с настройками при открытии меню.
- Старый, пока не подключённый `WindowPickerView` учитывает отказ привязки; общие AX-чтения resolver переведены на проверяемый клиент. Выбор конкретного окна в рабочий UI пока не подключён.

Debug и Release собраны через `xcodebuild` с `CODE_SIGNING_ALLOWED=NO`. Предупреждений Swift в окончательных сборках нет; остаются служебные сообщения sandbox/CoreSimulator и AppIntents metadata. Xcode project и shared scheme не изменялись; XCTest target всё ещё отсутствует.

Тестовый executable компилирует производственные менеджер, AX-клиент, геометрию, delay и настройки. AX read/write/raise заменены функциями тестового модуля; NSWorkspace/RunLoop настоящие, отдельные уведомления публикуются синтетически. Приложения пользователя не активировались и их окна не перемещались. Это **не** подтверждение работы с WindowServer/реальными AX-приложениями. В частности, приложение может применять позицию асинхронно: строгий readback способен вернуть ошибку до завершения такого перемещения; данные для повторного возврата при этом сохраняются.
