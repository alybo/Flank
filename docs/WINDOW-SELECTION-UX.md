# Предложение UX выбора окна — 10.09.2026

Статус: базовый сценарий принят пользователем и реализован 10.09.2026: конкретный AX-picker, drag, возврат, lifecycle и Undo. Реальные испытания drag ещё не выполнены; это экспериментальная функция. Ниже сохранена спецификация решения, включая идеи следующих итераций. Точный объём реализации/отличия и проверки см. `PROJECT.md` и `CHANGES-2026-09-10-window-selection.md`.

## Дополнение: стороны, пауза и отвязка

Обновление 10.09.2026: выбирается один внешний левый или правый край для одного окна. Все упоминания правой стороны в исходной спецификации ниже зеркально применяются к выбранной левой. Пауза «Скрывать выбранное окно» сохраняет AX-привязку и возвращает обычное управление окном; повторное включение скрывает ту же цель с её актуальной позиции. «Отвязать окно» очищает выбор после безопасного возврата.

Пользователь подтвердил жест отвязки: раскрыть закреплённое окно, начать drag с теми же клавишами и отпустить в появившейся области «Отвязать окно». Стрелка направлена внутрь дисплея. Жест доступен и для окна на паузе. Просто зажатие клавиш без drag ничего не отвязывает. Для другого окна остаётся обычное закрепление/замена. Новые сценарии и проверки: `CHANGES-2026-09-10-sides-and-pause.md`.

## Рекомендуемое взаимодействие

Два равноправных входа в один механизм привязки **конкретного окна**:

1. Для повседневной работы — перетаскивание окна с модификаторами в появляющуюся справа область.
2. Для первого использования, клавиатуры/трекпада и нестандартных окон — «Выбрать окно…» в меню и настройках, с перечнем отдельных окон.

Не требовать открывать большие настройки при каждом назначении. В настройках вместо выбора приложения показывать текущее окно: иконку приложения, заголовок, экран, состояние и действия «Выбрать другое…» / «Вернуть окно и выключить». Все способы выбора используют один контроллер; не создавать отдельный FlankManager внутри picker, как в старом неиспользуемом WindowPickerView.

## Жест добавления

1. Начать обычное перемещение окна за заголовок/доступную для перемещения панель.
2. Уже во время перемещения зажать **Control + Shift**. Комбинация настраивается.
3. Справа появляется отдельная карточка «Убрать в Flank». Начальная геометрия: ширина 252 points, без отступов справа, сверху и снизу. Область неподвижна и занимает всю высоту исходного дисплея; чёрная заливка и контур соответствуют Figma 47:54.
4. Когда курсор над карточкой, она выделяется и текст меняется на «Отпустите окно». Срабатывание происходит по отпусканию кнопки мыши, а не только по наведению.
5. Новое окно скрывается, появляется обычная ручка раскрытия. Краткое сообщение сообщает результат и даёт «Отменить» для нового назначения.

Отпустить модификаторы, нажать Escape, уйти из карточки и отпустить мышь — отменить **добавление**. Обычное перемещение окна, которое пользователь уже сделал, не откатывается. Приложение не перехватывает произвольные клики/набор текста.

Control предлагается зажимать после начала перемещения, чтобы не начинать жест как Control-click. Этот выбор требует испытаний; его совместимость со всеми приложениями и сторонними менеджерами окон не гарантирована.

**Почему не Option по умолчанию:** macOS Tahoe использует Option при перетаскивании для ускоренной раскладки окон. Край экрана тоже занят системным tiling; новая область примыкает к краю, поэтому конфликт системного tiling с drag требует ручной проверки; наблюдатель событий не может его подавить. Системные настройки пользователя не менять. [Apple: Tile windows on Mac](https://support.apple.com/en-mide/guide/mac-help/mchlef287e5d/26/mac/26).

После первой пробы пользователь выбрал высокую неподвижную зону: она упрощает попадание по вертикали. Это реализовано в `CHANGES-2026-09-10-static-drop.md`. После следующей итерации обе панели появляются справа налево из-за края за 180 мс; индикатор уменьшен до 30×102,5 pt, центр и отсутствие отступа сохранены. Подтверждённый drag не сбрасывается при запаздывании AX-снимков. Подробности: `CHANGES-2026-09-10-motion.md`. Макеты Figma 47:54 и 47:62 получены и внедрены; точный объём описан в `CHANGES-2026-09-10-figma.md`.

## Выбор из списка

Popover «Какое окно убрать?» открывается из строки меню или настроек. Каждая строка соответствует отдельному AX-окну, а не приложению:

- «Идеи» — Заметки · этот экран.
- «Покупки» — Заметки · этот экран.
- «Документация» — Safari · другой экран.

Иконка приложения + заголовок + экран позволяют различать окна без снимков содержимого. Если заголовок пустой/повторяется, добавить понятное уточнение позиции/размера; не показывать пользователю PID/CGWindowID. При необходимости подсвечивать кандидата неактивирующей рамкой, не менять фокус до подтверждения. Список доступен с клавиатуры; Enter выбирает, Escape закрывает. Не начинать с запроса Screen Recording ради миниатюр — для первого варианта нужны только метаданные/Accessibility.

Не прятать новое окно от простого наведения на строку: выбор подтверждается кликом/Enter. Неподдерживаемые окна отмечать понятной причиной, собственные служебные панели исключать. Для списка нескольких мониторов показывать только экраны, для которых уже определена и проверена политика скрытия.

## Замена, возврат и жизненный цикл

- Если слот уже занят, до отпускания показывать «Заменить окно …» и кратко сообщать, что прежнее окно вернётся. Не добавлять обязательное модальное подтверждение к каждому жесту.
- Сначала восстановить старую цель. При отказе не трогать новую, показать ошибку и сохранить возможность возврата старой.
- Для жеста сохранить безопасный frame до перетаскивания. После раскрытия окно возвращается туда, а не в частично вынесенное положение, в котором его отпустили над карточкой. API dock расширен аргументом restoreFrame; без него используется фактический frame назначения.
- На первом этапе ограничить жест исходным дисплеем и поддерживаемым внешним правым краем. Межэкранное назначение не включать до определения позиции возврата и поведения внутренних границ дисплеев.
- «Отменить» относится только к последнему ещё актуальному назначению: вернуть новую цель, а при замене восстановить прежнюю привязку только если её окно всё ещё существует и восстановление новой цели удалось. Любая новая операция инвалидирует старое undo; никогда не угадывать другое окно по заголовку.
- Нужен AXObserver закрытия конкретного окна. Если оно закрылось, сообщить «Окно закрыто» и предложить выбрать новое, не подменять его первым окном того же приложения.
- Между запусками не считать PID, bundle ID, заголовок или старый CGWindowID доказательством идентичности окна. При неоднозначности — повторный выбор. Меняющийся заголовок во время сессии не меняет её цель.

## Техническая реализация

**WindowCatalog / WindowSelectionController.** Получать окна через AX каждого подходящего приложения; сохранять фактическую AX-ссылку и owner PID на время сессии. Проверять role/subrole, размер, возможность изменения позиции, minimized/fullscreen и собственные панели. Перед commit заново проверить жизнеспособность кандидата. Не использовать текущий resolver по ближайшему центру как единственное подтверждение идентичности окна.

**WindowDragCaptureController.** Наблюдать mouse down / drag / up, flagsChanged и отмену. При mouse down получить кандидата под курсором и его начальный frame, затем подтвердить перемещение самого окна: origin меняется согласованно с движением указателя, размер остаётся устойчивым. Если перетаскивают текст, файл, вкладку, scrollbar или выполняют resize, карточку не активировать. AX читать ограниченно и только для захваченного кандидата, не сканировать все окна на каждом mouseMoved.

Для hit testing подходит [AXUIElementCopyElementAtPosition](https://developer.apple.com/documentation/applicationservices/1462077-axuielementcopyelementatposition): она возвращает элемент с учётом z-order; из дочернего элемента можно получить окно через [kAXWindowAttribute](https://developer.apple.com/documentation/applicationservices/kaxwindowattribute). Проверять типы и ошибки, использовать AX/CG-координаты.

Наблюдение событий доступно через [NSEvent.addGlobalMonitorForEvents](https://developer.apple.com/documentation/appkit/nsevent/addglobalmonitorforevents%28matching%3Ahandler%3A%29). Важное ограничение: монитор получает события асинхронно и **не может подавить их обработку macOS или целевым приложением**. Поэтому нельзя обещать автоматическое устранение конфликта с системной раскладкой. У некоторых приложений/нестандартных панелей drag может быть неоднозначен; в этом случае назначение не выполнять, оставить выбор из списка.

**DropTargetPanel.** Отдельная неактивирующая визуальная панель с `ignoresMouseEvents = true`; она не забирает drag и mouseUp у исходного приложения. Попадание определяется по координатам курсора. При жесте временно отключить существующий reveal overlay, чтобы он не перехватывал отпускание и не раскрывал старую цель. После завершения восстановить обычный режим.

**Commit.** После mouseUp дождаться завершения/стабилизации нативного перемещения с ограниченным сроком, перепроверить кандидата и модификаторы события отпускания, затем выполнить транзакцию назначения. Не начинать AX-анимацию одновременно с системным drag. Ошибки, Escape, blur/потеря сеанса, изменение дисплеев, отзыв Accessibility и уничтожение окна очищают candidate, панель и отложенные действия.

Состояния жеста: `idle → candidate → dragging → eligible → armed → committing → idle`. Любая отмена возвращает в idle. Токен жеста независим от UUID привязанного окна; старые callback не могут назначить прежнего кандидата после нового жеста.

## Порядок внедрения и проверки

1. Общий механизм выбора конкретного AX-окна, новый picker без отдельного менеджера, отображение выбранного окна в настройках.
2. Lifecycle observer, явно заданная безопасная позиция возврата, атомарная замена и undo.
3. Экспериментальный modifier-drag, отдельная drop-панель, cancellation и настройка клавиш.
4. Реальные испытания с системным tiling включённым/выключенным, обычным AppKit, Safari, Chrome/Electron, трекпадом и изменением модификаторов во время жеста.

Критические проверки: два похожих окна одного приложения; drag текста/файла/вкладки не назначает окно; отпускание вне карточки; Escape; потеря модификатора перед mouseUp; освобождение клавиш сразу после mouseUp; ошибка восстановления прежней цели; окно закрывается в момент drag/commit; блокировка экрана; смена дисплеев; конфликт с native tiling; быстрый повторный жест; отмена после изменения уже назначенного окна.

Критерий выпуска drag: он назначает именно перетаскиваемое окно и не вмешивается в обычное перемещение, если пользователь не подтвердил жест. До интеграционной проверки drag считается экспериментальным; совместимость публичных API со всеми приложениями не гарантируется.
